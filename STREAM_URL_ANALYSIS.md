# How Telegram Web Stream URLs Work & Where They Originate

The very first URL comes **directly from Telegram Web's own DOM**, generated by Telegram's internal media player.

The extension **does not generate the URL itself**—instead, it forces Telegram Web's own frontend to create the URL, and then reads it out of the DOM.

Here is the exact trace of how that happens:

---

## 1. For Audio (Voice notes, Songs)

From `extension/content-ui/index.iife.js`:

```javascript
async resolveAudioStreamUrl(t, n = 15000) {
  const r = this.getAudioTitle(t);
  let i = this.findAudioStreamUrl(r);
  if (i) return i;

  // 1. If not already playing, simulate a user click on Telegram's Play button!
  const u = t.querySelector(".audio-toggle");
  const isPlaying = u?.classList.contains("playing") ?? false;
  if (!isPlaying) {
    (u ?? t.querySelector(".audio-play-icon"))?.click();
  }

  // 2. Poll the DOM every 200ms waiting for Telegram to create <audio src="...stream/...">
  const c = await new Promise((resolve, reject) => {
    const m = setInterval(() => {
      const x = this.findAudioStreamUrl(r);
      if (x) {
        clearInterval(m);
        resolve(x);
      }
    }, 200);
  });

  // 3. Pause the audio so it doesn't actually play out loud
  if (!isPlaying && u?.classList.contains("playing")) {
    u.click();
  }
  return c;
}
```

And in `findAudioStreamUrl`:

```javascript
findAudioStreamUrl(title) {
  for (const audio of Array.from(document.querySelectorAll("audio"))) {
    const src = audio.src;
    if (src && src.includes("stream/")) {
      const info = this.parseStreamUrlInfo(src);
      if (info?.fileName === title) return src;
    }
  }
  return null;
}
```

### Step-by-Step Flow:
1. When you click the extension's download button, the media does not have a stream URL yet.
2. The extension programmatically clicks the audio play button in the Telegram chat bubble.
3. Telegram Web's JavaScript initializes playback: it creates or updates an HTML5 `<audio>` element with a `src` attribute.
4. The extension polls `document.querySelectorAll("audio")` until it detects the `src` attribute containing `stream/`.
5. The extension immediately grabs `audio.src` and clicks the pause button so the user doesn't hear the audio start playing.
6. That captured `src` is the **initial URL** dispatched to `downloader/index.iife.js`.

## 2. For Videos and Images

For videos and images in restricted channels, Telegram Web already has a full-screen media viewer with quality selection, but hides the download option if the channel has restricted saving enabled (`no-forwarding`).

The extension does two things:

### 1. Unhides Telegram's download buttons:
```javascript
t.forEach(i => {
  const isHidden = i.classList.contains("hide");
  if (isHidden) i.classList.remove("hide"); // Removes Telegram's restriction!
});
```

### 2. Automates opening the viewer:
When you click the extension's download icon on a video in chat:
- It clicks the thumbnail to open Telegram's built-in media viewer (`.media-viewer-whole`).
- Telegram attaches the video stream to `<video src="...stream/...">`.
- It opens Telegram's quality menu (`.quality-download-options-button-menu`), selects the highest resolution (e.g. 1080p / 4K), and clicks the viewer's download action.

---

## Why does the URL contain `stream/`? (Under the Hood)

1. Telegram media files are stored on Telegram's MTProto backend servers as encrypted 512KB / 1MB chunks.
2. Browsers cannot natively stream MTProto data over WebSocket into `<audio>` or `<video>` tags.
3. To bridge this, **Telegram Web registers an internal Service Worker** that listens to routes matching `/stream/*`.
4. Telegram's frontend constructs a synthetic URL containing JSON metadata:
   ```text
   https://web.telegram.org/k/stream/%7B%22location%22%3A%7B%22id%22%3A%22...%22%7D%2C%22mimeType%22%3A%22audio%2Fmpeg%22%2C%22fileName%22%3A%22song.mp3%22%7D
   ```
5. When the extension runs:
   ```javascript
   fetch(url, { headers: { Range: "bytes=0-" } })
   ```
   **Telegram's Service Worker intercepts that HTTP request**, translates it into MTProto `upload.getFile` requests to Telegram's servers, decrypts the payload, and serves it back as standard HTTP chunks (`206 Partial Content` with `Content-Range: bytes 0-1048575/total`).

---

## Summary

The extension never connects to Telegram's API directly. It **simulates user interaction** (clicking Play or clicking the media viewer), waits for **Telegram Web's own JavaScript and Service Worker** to instantiate the stream URL on `<audio src>` or `<video src>`, and then intercepts that URL.
